# PDF 本地解析 V2 设计文档

> 状态：已实现并验证（2026-07-21）
> 代码：`openviking/parse/parsers/pdf.py` · 配置：`PDFConfig.local_version`（默认 `"v2"`，`"v1"` 保留用于兼容性回退）
> 测试语料：`cyclone/tests/data/{CyClaw-2pages, CyClaw用户操作手册, test-pdf}.pdf`

## 1. 背景与问题

V1（`_convert_local_sync`）的本地转换流程是：每页先 `extract_text()` 全页文本、再 `extract_tables()` 表格、直接拼接进 Markdown。在飞书/Chromium 导出的 PDF 上产生**整页内容重复**：

- 飞书导出的 PDF 用**铺满整页的白色纯填充矩形**做背景框（实测 CyClaw 手册每页 0 条真线段、3+ 个 540×786pt 填充矩形）；
- pdfplumber 默认 `lines` 策略基于 `page.edges` 检测表格边界，而 edges **包含所有矩形的边（含无描边纯填充矩形）**，于是整页被闭合成一个 1 列巨型"表格"（面积比 ~84.5%，被内部横条切成 2 行）；
- `extract_text()` 提取包括表格区域在内的全部文字——文本与"表格"内容完全一致，拼接即重复。

后果：中间 Markdown 全文重复一份，污染下游 chunk 切分与检索（重复 chunk、浪费 token、搜索重复命中）。实测 92 页手册 V1 检出 **149 个表格，其中 59 个是整页误检**，且真实表格被背景框边污染出幻影行/列。

## 2. V2 设计总览

```
PDF → 标题检测(书签/字号, 与 V1 共用)
    → 逐页：
        表格: 严格边界检测 → 整页误检过滤 → 丢弃全空列 → Markdown 表格
        文本: 字符级排除表格区域(page.filter) → extract_text_lines → 行重建(段落合并/列表/代码围栏)
        图片: 尺寸过滤(图标/背景) → 裁剪渲染 PNG → 存储
        混排: 文本行/表格/图片按 Y 坐标归并，保留页内原始顺序
    → 全局清理(\x01 → 空格, NFKC) → Markdown
```

核心不变量：**文本与表格零重叠、零丢失**。表格区域内的字符只出现在表格里，区域外的字符全部保留在文本里（字符中心点判定归属）。

## 3. 表格边界检测（核心）

对页面对象按类型分类，分别作为"双向边"或"仅竖边"送入 pdfplumber `explicit` 策略：

| 对象 | 判定 | 横边 | 竖边 | 理由 |
|---|---|---|---|---|
| `page.lines` 真线段 | — | ✓ | ✓ | 真正的表格线 |
| 描边矩形（stroke=True 或 linewidth>0） | — | ✓ | ✓ | 有边框表格 |
| 细条填充矩形（短边 < 3pt） | 分隔线 | ✓ | ✓ | 行/列分隔条 |
| **大填充矩形（背景框）** | 背景 | **✗ 丢弃** | **✓ 保留** | 见下 |

**为什么背景框"弃横留竖"**（两条实测教训）：

1. **横边必须弃**：背景框横边位于页眉/页脚位置（top≈28/814），与竖边闭合后把整页变成假表格——这是 V1 重复问题的根源。若四条边全保留（默认策略），92 页手册产生 59 个整页误检，其中还有 2 行×2 列形态（p5），**行列数过滤挡不住**。
2. **竖边必须留**：飞书表格常缺左外框线（半边框表），其首列左边界恰好与背景框竖边（正文左边界）重合。若四条边全弃（初版严格策略），首列（如"端/助手页面/后台管理"）会被挤出表格成为表外孤儿文本。背景框竖边与表格内部竖向分隔线组合后恰好闭合出正确的首列。

配套两道兜底：

- **整页误检过滤**：表格 bbox 面积 > 页面 75% 且只有 1 列 ⇒ 判定背景框误检，丢弃（防背景框竖边+多条横分隔线意外闭合整页）；
- **全空列丢弃**（`_drop_empty_cols`）：背景框竖边偶尔引入无内容的幻影空列，提取后按"所有行均为空"丢弃；
- **单元格换行合并**（`_join_cell_lines`）：pdfplumber 对视觉换行的单元格返回 `\n`，裸写会破坏 Markdown 表格行（必须单行）。CJK 字符之间的换行多为排版软换行（常断在词中间，如"使用技\n能"），直接相连；其余边界（拉丁词、CJK↔拉丁）补空格防粘连。

检测异常时自动回退 pdfplumber 默认策略（启发式过滤仍生效）。

**跨页续表**（漏行回收 + 合并，`_recover_leaked_rows` / `_stitch_cross_page_tables`）：飞书续页首行无顶边框（顶边即背景框顶边，已被"弃横"规则丢弃），导致首行漏出表格、续表首行数据被误当表头。修复分两步，均采用苛刻几何约束、失败退回原样：

1. **漏行回收**：页面首表上方被 ≥2 条与列边界对齐、从表体向上延伸的竖边**实际包围**的表外文本行，按列 x 边界把字符聚回单元格，prepend 到表 rows；单列字符行（单元格折行）CJK 并入上一回收行。正文段落周围没有竖边，不可能误回收；
2. **跨页合并**：Page N 首块为表且前页末块为表时，三重守卫同时满足才合并——①列数相同且列边界 x 对齐（5pt）；②前页表底贴近内容底（表被页边界**切断**而非自然结束，同模板相邻表靠此条拒绝）；③续表顶贴近内容顶。续表首行与前页表头重复则丢弃；支持 3+ 页链式合并（合并后表的实际结束页随之前移）。

## 4. 文本提取：字符级排除 + 行重建

- 用 `page.filter()` 剔除中心点落在任一表格 bbox 内的字符，再对过滤页做 `extract_text_lines()` 按行成块；
- 相比 V1 候选方案的 Y 整宽切片：不丢表格旁侧文字、不引入切片间隙丢字（实测 Y 切片 + 固定页眉阈值会吃掉页首正文行，如"◦ 3.5 技能管理"）；
- `extract_text_lines` 不可用时兜底整页 `extract_text()`。

**文本行重建**（`_reconstruct_text_lines`）：`extract_text_lines` 给出的是视觉行，若全部用 `\n` 拼接，Markdown 预览会把段落内单 `\n` 折叠成空格，列表/元信息/ASCII 图全部塌成一段。重建规则：

1. **段落软换行合并**：上一视觉行排满整行（右端距页面文本右缘 < `V2_FULL_WIDTH_TOLERANCE=14pt`，约 1.3 字符——标点压缩/避头尾会让两端对齐的行尾短 0.5–1 字符）时，当前行是续行，按 CJK 规则并入（CJK↔CJK 直连、其余补空格）。源文件不再断词，检索友好；
2. **列表归一**：`•`→`- `、`◦`→`  - `（缩进子列表）、`▪`/`‣`→`- `，`N.` 有序项保留，连续列表项单行相连；
3. **代码围栏**：含 box-drawing 字符（`├└│─` 等）的连续行（含相邻 `N ` 行号行）→ ` ``` ` 围栏，ASCII 树状图预览不再塌陷；
4. **章节编号行保护**：`1.5 xxx` 类编号行强制另起逻辑行，不并入上一段落；
5. **`\x01` 预归一**：Chromium PDF 行内空格是 `\x01`（非 `\s`），重建前先替换为空格，否则行首模式匹配全部失效；
6. 逻辑行/块之间以空行分隔，预览各行独立。

## 5. 图片提取

复用 V1 的裁剪渲染（`page.crop(bbox).to_image()` → PNG → storage），新增两道尺寸过滤：

- 宽或高 < 20pt ⇒ 图标/装饰，跳过；
- 面积 > 页面 90% ⇒ 页面背景图，跳过。

## 6. 编码清理（与 V1 一致）

- `\x01`（U+0001 SOH）→ 空格。本质是 Chromium/Skia 生成器给"排版间隙"（中英文自动间距）打的标记：字体子集 gid 1 的空白字形在 ToUnicode CMap 中被映射为 U+0001 而非 U+0020（实测 CMap 含 `<01> <0001>`，无任何 U+0020 条目）。替换为空格是检索友好选择；
- NFKC 归一化（CJK 兼容字符）。
- **已知暂缓项**：康熙部首字符（U+2E80–U+2EFF，如 ⻚⻆⻜，约占字符量 1.1%）NFKC 不覆盖，经决策**暂不处理**；若重启，正确做法是从 Unicode NamesList.txt 交叉引用一次生成全量静态表。

## 7. 配置与接入

```python
PDFConfig()                              # 默认 local_version="v2"
PDFConfig(local_version="v1")            # 回退旧实现（兼容性保留）
```

- `_convert_local_sync` 入口按 `local_version` 分发，V1 路径零改动；
- `auto` 策略下 V2 失败仍会回退 MinerU（行为不变）；
- `PDFConfig` 默认 `flat_layout=True`：PDF 转换出的标题层级来自书签/字号启发式，层级不可靠（常跳级，如 H1→H3 无 H2），嵌套目录布局会产生同名多级子目录（`手册/手册/手册_N.md`），故 PDF 资源统一平铺为一级文件；
- V2 关键阈值均为 `PDFParser` 类常量：`V2_FILL_RECT_MAX_SIZE=3.0`、`V2_FULL_PAGE_AREA_RATIO=0.75`、`V2_MIN_IMAGE_SIZE=20.0`、`V2_MAX_IMAGE_AREA_RATIO=0.9`。

## 8. 验证结果

语料级基准（`cyclone/tests/test_pdf_extract_md.py` 与 V2 产出一致）：

| PDF | 页数 | V1 表格数 | V2 表格数 | 图片 | 页内重复 |
|---|---|---|---|---|---|
| CyClaw-2pages | 2 | 3（含误检） | 1 | 0 | 无 |
| CyClaw用户操作手册 | 92 | 149（含 59 误检） | 85（跨页合并 -8） | 54 | 无 |
| test-pdf | 12 | 4 | 4 | 40 | 无 |

- 页内零重复不变量：表格单元格内容（≥20 字符归一化片段）不得出现在同页文本块——全语料通过（跨页合法重复引用不计，如附录索引表与正文描述同一字段）；
- 半边框表首列回归：CyClaw-2pages 表格保持 3 列（端/主要使用者/核心价值）；
- 官方回归：`tests/parse/test_pdf_bookmark_extraction.py` + `test_parser_config_wiring.py` 22 passed；
- 性能：92 页 + 54 图 ≈ 11s。

## 9. 已知边界（第一层几何解析的固有上限）

- 多栏阅读顺序（Y 混排在双栏下会交错）→ XY-cut 或阅读顺序模型；
- 无边框表格（需 text 策略或 TSR 模型）；
- ~~跨页表格合并~~ ✅ 已实现（漏行回收 + 三重守卫合并，见 §3）；
- 页眉页脚未过滤（方案：跨页重复文本频率判定，不用固定阈值）；
- 扫描件 OCR、公式、图表内容理解 → 路由 MinerU/VLM（当前按决策不做）。
